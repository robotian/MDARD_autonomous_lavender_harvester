# sim/ — Isaac Sim scene (`sim/scripts/setup_scene.py`)

`setup_scene.py` runs via `--exec` in the Isaac streaming app, `./sim` mounted at `/sim`. Real-robot params, chassis_link/IMU findings, flatten_urdf fixes → skill `add-real-robot`; URDF pipeline → `scripts/CLAUDE.md`.

## Start, spawn, reset

- **Import** (`import_urdf_if_needed`, `MODEL_ASSETS`): once per model, cached in `sim/generated/<model>/`, invalidated by `.import_stamp` (import settings + URDF mtime/size) or `FORCE_REIMPORT=1`. Each model's `usd_dir` is deleted first, or the importer writes `<model>_1/`, `<model>_2/`, ….
- `main()` imports every model before building the scene (the importer opens its output as the stage, so it can't run later); a model whose URDF changed after start is refused at spawn. Then: world built, timeline left **stopped**, `sim/generated/fleet/state.json` written (`scene: ready`, `models`, `default_poses`, `lavender_rows`, `chargers`, `scene_source`), `spawn_loop` runs.
- **Spawn:** `spawn_loop` polls `spawn_request.json` (`{id, robots: [{model, x, y, yaw}]}` (yaw in degrees) from `scripts/fleet_ctl.py`; slot = list index, namespace `robot_namespace(slot, model)`). `parse_request`: known model, |x|,|y| <= `SPAWN_LIMIT` 38 m, >= 1 m apart, unique namespaces; a rejection leaves robots alone (`last_error`). `spawn_fleet` stops the timeline, spawns, re-aims the viewport, plays. Successes go to `applied_request.json`; answered ids are never replayed.
- **Replacing robots restarts the sim** (~27 s): with robots present, `fleet_ctl.spawn` writes the request with `at_start: true` (ignored by the running loop) and `docker restart`s; at start the pending request is spawned (fallback `applied_request.json` if rejected), then `boot: done` (what `wait_scene` waits for). Not in-place: `DeletePrims` on `/World/<ns>` + `/Graphs/<ns>` made the headed RTX renderer abort (SIGABRT in `libnrend.so`). Spawning into an empty scene stays in place.
- **Deleting a graph doesn't run its ScriptNodes' `cleanup()`**: script nodes that create rclpy nodes register them in `fleet_nodes.py`; `spawn_fleet` destroys them. Do the same for any new one.
- **Plants** (`control.json` `{id, action: "plants", hide: [object_id...], show: [object_id...] | "all"}`, `scripts/fleet_ctl.py plants`): harvested / not harvested (`plants_request` → `set_harvested`, visibility on the root layer only): a farm plant's `ready` child is hidden and its `harvested` child (05 model) shown; a plant without them is hidden. Colliders stay (PhysX ignores visibility). Not a swap of the instance's prototype at runtime: that turned every RTX frame black (2026-10-21). `index_plants` maps `customData object_id` → prim at scene ready; `state.json` gets `plant_count`, `plants_hidden`, `actions` (an older sim resets its timeline on an unknown action: `fleet_ctl.plants` refuses unless `plants` is advertised). Lost on a sim restart: the web UI's operation page replays what the database says.
- **Reset** (no restart): `control.json` `{id, action: "reset"}` → `reset_timeline` (stop, 5 frames, play, ~3.5 s) → `state.json` `reset: {id, state: done}`. `fleet_ctl.reset` stops the robot containers around it so no robot process acts on the restarted scene.
- `default_poses(n)`: `SCENE_LANES` (3) robots 1.6 m apart at x=0, further ranks 2.5 m behind. `platform/odom` and `ground_truth` TF start at zero at the spawn pose (no spawn yaw); GPS has it (datum = world origin, X/Y = East/North).
- **Save As in a running sim** reopens the file as a new, *stopped* stage: `current_stage` takes the open stage on every request, and `spawn_loop` replays the timeline if robots exist. Never cache the stage from `main()` (spawns then fail with `Stage.DefinePrim ... did not match C++ signature`).
- `apply_kit_settings` sets `/app/omni.graph.scriptnode/opt_in` true; otherwise a dialog appears whose **No** disables every robot script node.

## Physics engine (`SIM_PHYSICS` physx|newton)

- `select_physics_engine()` in `main()`, before the stage exists: `newton` enables `isaacsim.physics.newton` (0.7.14, Newton 1.2.0, MuJoCo-Warp solver; its `auto_switch_on_startup` makes it the active engine of `isaacsim.core.simulation_manager`) **and** `isaacsim.physics.newton.tensors` (the `omni.physics.tensors` backend named "Newton": without it the engine steps but every articulation/odometry/joint-state node fails with "Failed to find simulation backend"); a failed switch logs the traceback and runs PhysX. `state.json` `physics` = the engine running, `physics_requested` = the setting (the web UI shows a mismatch). PhysX stays the default: every robot's drive, friction and mass tuning (`model_params.yaml`, the velocity calibration) was done on it; Since 2026-10-20 every model's drive is calibrated for both (`scripts/vel_tune/calibrate_all.py`: all within 2 % in the `calibrate_velocity.py` sweep, except r100 on Newton at 1.0 rad/s, 7 % fast).
- Newton parses the USD stage at the first physics step (`NewtonStage._initialize_newton_impl`, `newton.ModelBuilder.add_usd`): it reads UsdPhysics masses/densities, materials' friction, joint drives (stiffness/damping/targets, `force_position_velocity_actuation`), `PhysxSceneAPI.timeStepsPerSecond` and handles instanceable prims; any USD change (`on_change`) re-parses at the next step. The URDF importer already authors `newton:selfCollisionEnabled = 0` on the articulation root (`spawn_one` sets it again, harmless). `PhysxSchema` tuning is ignored: `spawn_one` skips `enable_wheel_ccd` / `set_articulation_iterations` under Newton (`apply_wheel_friction`'s UsdPhysics friction still applies, its PhysX combine mode doesn't). `NewtonMimicAPI` is still removed (`configure_arm_drives`).
- **What it took to make a robot drive (2026-10-20, j100 on the empty scene; each one alone was not enough):**
  - **MuJoCo's own contacts** (`cfg.solver_cfg.use_mujoco_contacts = True`, set in `select_physics_engine`; the extension's default is Newton's collision pipeline since 0.7.8): with Newton's pipeline the robot sat right but the first wheel rotation launched it metres into the air.
  - **`NEWTON_PHYSICS_HZ` (240) instead of `PHYSICS_HZ` (60)**: MuJoCo's default contact time constant (0.02 s) needs dt <= 0.01 s, and the arms' stiff position drives are unstable at 60 Hz. `select_physics_engine` swaps `PHYSICS_HZ` / `PHYSICS_FRAME_DT` (the physics scene and the script nodes' `dt` follow).
  - **Wheel torque cap** (`cap_wheel_drives`, `NEWTON_WHEEL_MAX_FORCE` 20 N*m, `DriveAPI maxForce`): the wheels' velocity drive (damping 1000) is an unbounded MuJoCo actuator otherwise; a tyre momentarily held by a soft contact got hundreds of N*m and the chassis was catapulted (0.2 m/s commanded, 2 m/s and tipped). PhysX bounds the same drive through its rigid contacts. 20 N*m suits the Jackals but starves heavier robots (a200_0284 turned at 0.83 of 1 rad/s, a 0.5/0.5 arc at 0.3 of its speed): per-model `wheel_max_force` under `robots.<m>.newton` in `model_params.yaml` (calibrate_all: 6 x URDF mass x wheel radius, at least 20; a200 60-70, a300 80-100, r100 90).
  - **No `WheelBrake` under Newton**: its runtime stiffness writes are synced into MuJoCo actuator gains in position-actuator form (`gainprm[0] = kp`, `biasprm = [0, -kp, -kd]`, `isaacsim.physics.newton.tensors` `ctrl_direct_sync`), and a velocity drive loses its gain once the brake releases. MuJoCo's implicit integrator holds the damped wheels still anyway.
  - **Wheel damping** (`wheel_damping` under `robots.<m>.newton`, N*m*s/rad, set by `cap_wheel_drives`; unset = the importer's 1000): MuJoCo integrates the velocity drive's damping implicitly, i.e. as kv * dt of extra inertia on the wheel joint (1000 at 240 Hz: ~4.2 kg*m^2, against ~0.003 of a Jackal wheel). With the torque cap saturated the wheels then spin up/down at ~cap / 4.2 (j100_0921: 4.6 rad/s^2) and the chassis runs non-physically ahead of / behind them (0.70 m/s for 0.50, roll-back -0.17 m/s after a stop): Nav2's MPPI, reading that speed, oscillated -0.3..0.8 m/s on a straight path and tipped the robot (2026-10-20). 20 fixed it (5 coasts at a stop); Newton applies this damping per radian (1000 converted gave the same result as the importer's 1000). a200/a300 (every model, 2026-10-20): 50 (a200_0284 at 1000: 0.77 m/s for 0.50, roll-back -0.19; a300_00036 0.60 / -0.06; at 50 both 0.54, none, and stop faster than at 20), Newton drives recalibrated with it (calibrate_all, sweeps pass; turns start ~30-40 % over a step, the skid-steer chassis turning at 36-61 % of the command open loop). j100 (generic), j100_0922, j100_0936 and r100 still run 1000 with calibrations made on it.
  - Results (empty scene): j100 open loop 0.2 m/s -> 0.19 m/s average with no coast, 0.5 -> 0.54 at the end, in-place rotation ~1 rad/s for a 1.5 rad/s command (PhysX open loop: ~2 %); closed loop (`VELCTL=1`, PhysX-tuned gains) a200_0333 0.5 m/s -> 0.46 average / 0.50 at the end, straight, 0.23 m coast, but a 0.5 rad/s in-place rotation gives only 0.07 rad/s; j100_0921 (arm) rests level at z 0.060, the arm holds (joints 0.00 / 0.00), 0.3 m/s -> 0.28 average, 4.5 cm coast. `WheelBrake`-free resting robots don't creep. These were before calibration (step 5 of Velocity control below); a300 and r100 (`BodyDrive` through the tensor API, sideways within 0.1 %) drive since. Not yet done: arm moves (MoveIt).
- **Per-frame time under Newton is 11 steps (0.0458 s), not `PHYSICS_FRAME_DT`'s 12**: VelCtl and the Newton IMU take the real frame time from a `PhysTime` (`IsaacReadSimulationTime`) node wired only under Newton; with the assumed 0.05 s the closed loop held every speed at 0.90 of the command.
- **Same frame on both engines: `SIM_RATE_HZ` must divide 60 and 240** (20, 30, 60). At the profile's old 22, PhysX ran 2 steps (33.3 ms) per frame and Newton ~11 (45.8 ms, Newton carries the remainder, PhysX drops it), so the same Nav2 params behaved differently: odom/TF/scan updates 30 vs 22 per sim second, and Nav2's wall-paced 20 Hz controller saw 3-frame cycles (7.3 Hz in sim time) vs 2 (15 Hz). At 30 both run 33.3 ms (2 x 1/60, 8 x 1/240), PhysX unchanged; j100_0921's Newton drive measured the same (step test within ~1 %, 2026-10-20). Real-time factor still differs with GPU load (Newton 0.74-1.37 that day): `rateLimitFrequency`, as a carb setting or on Kit's command line, did not cap the frame rate (Isaac's loop runner).
- **Drive tuning per engine**: `model_params.yaml` `robots.<m>.newton: {vel_ctl: ...}` overrides apply only under Newton (`load_model_params`). Tuned: j100_0921 (sweep within 1 %, wobble < 3 %). Other models still run Newton with their PhysX gains (which boost yaw for PhysX's ~2 % open-loop turning): expect overshoot until tuned the same way (`vel_tune/step_test.sh` open loop first, then trim).
- **Ground plane under Newton** (`newton_ground_plane`, called after `build_world`): `/World/ground`'s box collider is disabled and an invisible `UsdGeom.Plane` at its top (z=0) with the same physics material takes over. MuJoCo has no exact cylinder-box contact; on the box the wheels' contacts jittered, giving 13-33 % yaw wobble, 2-4 deg body chatter and the farm-scene start-up drift. On the plane: wobble < 3 %, tilt < 1 deg.
- **Wheel friction under Newton** (`apply_wheel_friction`): Newton reads only a collider's own physics binding (the body's left the wheels at mu 1.0) and MuJoCo takes the larger friction of two geoms unless one has priority: the material is bound on each wheel collider too, with `mjc:priority` 1, so the wheel's 0.3 wins over the ground's 0.9 (PhysX's `min`).
- **Arm drive gains under Newton** (`NEWTON_ARM_GAINS`, per radian, `configure_arm_drives`): Newton reads USD angular drive gains per degree and scales by 57.3, so the PhysX values (joint_2 damping 1e6) became 5.7e7 N*m*s/rad against a 42 N*m cap and the arm crept (stow 1.7-2.0 rad off). Now realistic stiffness/damping per joint: stow/ready/stow within 0.01 rad. MoveIt trajectories not yet checked under Newton. The gripper joints get `NEWTON_GRIPPER_GAINS` (20 N*m/rad, 1 N*m*s/rad): with the PhysX values the 2F Lite's bottom joints (10 N*m cap) flailed past their limits and cut_stem's gripper never followed (2026-10-20).
- **Poses are in Fabric only** (`omni:fabric:worldMatrix` on body prims; USD keeps the spawn pose), so every per-frame pose read goes through `fleet_pose.world_matrix(path)`: PhysX -> `ComputeLocalToWorldTransform`; Newton -> the nearest rigid-body ancestor's Fabric world matrix (`IFabricHierarchy.get_world_xform`) x the prim's USD offset from it, cached (`fleet_pose.reset()` at spawn). Verified against Newton's own `body_q` to the millimetre (`FLEET_DEBUG` logs both). `IsaacComputeOdometry`, `IsaacArticulationController` and the TF publishers go through the engine-neutral tensor / usdrt APIs on their own.
- **Lidars**: `fleet_pose.ray_caster()` -> PhysX scene queries, or `fleet_newton.Raycaster` (`newton.sensors.SensorTiledCamera` over the Newton model, one kernel launch per cast with the rays in world space, shape BVH refitted once per physics step; `None` until Newton has parsed the scene, so the scripts publish nothing before the first step). Shapes without Newton's VISIBLE flag (collision-only prims such as the lavender cores) aren't hit.
- **IMU**: `isaacsim.sensors.experimental.physics` is a PhysX plugin (not enabled under Newton); `IMU_NEWTON_SCRIPT` differentiates the articulation root's velocity (`Articulation.get_velocities`, world frame) over `PHYSICS_FRAME_DT`, adds gravity and rotates into the IMU body's frame. Assumes the IMU body is the root's (true for the MTU robots). Noisy: differentiating over a 50 ms frame turns MuJoCo's contact jitter into ~1 m/s^2 (z read 9.3-11.4 at rest on j100_0921); a low-pass, or Newton's `SensorIMU` (needs `body_qdd` from the solver), would improve it.
- **Lidars under Newton, live** (a200_0333): 2D scan at the frame rate, the VLP16 cloud once per `LIDAR3D_TICKS_PER_SCAN` frames (2625 ground hits on the empty scene), no script errors; the Warp render/BVH kernels compile on first use (~3 s).
- **Scene parse** (`NEWTON_IGNORE_PATHS`, default `/World/lavender /World/shrubs /World/trees`; `install_newton_parse_hook` wraps `ModelBuilder.add_usd` to add them to `ignore_paths` and logs "newton parsed the stage in N s"): Newton makes a shape of every mesh, instance proxies included, and the farm's foliage is 1900 instanced plant meshes of ~190 k points (362 M points; they are the plants' colliders too) plus 2300 tree/shrub meshes: unskipped, the parse pinned the main thread for 10+ minutes and never stepped. Plain prim paths are what works: the importer hands them to `UsdPhysics.LoadUsdPhysicsFromRange` as `excludePaths` (colliders go too) and matches them as regexes against visual meshes/bodies/joints; a pattern with `.*` only does the latter. With the default the farm parses in 6 s (163 shapes) and runs at real time; the plant cores, rocks, arch, chargers and ground stay, so driving is unchanged, but Newton's lidars don't see foliage. j100_0921 drifted 28 cm / 14 deg from its spawn pose while Newton settled at start (not seen on the empty scene; unexplained).
- First play on Newton compiles Warp kernels (~1 min with a warm cache, longer the first time; CUDA graph capture after the first step). `FLEET_DEBUG=1` logs `fleet_newton.debug_report()` (bodies with z/roll/pitch, shapes, MuJoCo geoms and contacts) at 0.5 s and 5 s. A scene Reset re-parses Newton and recovers from a NaN state without a sim restart.

## Per-robot graph

One OmniGraph per robot (`isaacsim.ros2.bridge`, topics relative to the namespace) plus a USD camera per camera.

- **cmd_vel is `TwistStamped`** (as on the real Jazzy platform). `ROS2SubscribeTwist` only takes `Twist`, so `CMD_VEL_SCRIPT` (ScriptNode with an rclpy subscriber) replaces it. Publishers must send stamped.
- A command older than `CMD_VEL_TIMEOUT_S` (0.5 s, sim time via the `stamp` input) stops the robot, like the real platform; publishers must repeat it (teleop, Nav2 and `drive_test.py` do). Before, a robot whose sender died drove on forever, also after a Reset.
- Chain: cmd_vel → `VelCtl` → `Diff` (`DifferentialController`) → `DriveFront`/`DriveRear`; `Odom`. Their `chassisPrim` is `chassis_prim()`, the one prim with `ArticulationRootAPI`, read at spawn (a `chassis_link` override is honoured). A wrong one only fails at runtime ("Articulation controller failed"); more than one root is refused at spawn.

### Velocity control (`VEL_CTL_SCRIPT`)

- Feed-forward + PI on achieved forward speed / yaw rate (`VELCTL_DEFAULT`, per-model `vel_ctl` in `model_params.yaml`, `VELCTL=0` = open loop). Target within ~10% over 0-1 m/s, 0-1 rad/s; check with `scripts/calibrate_velocity.py` (stows the arm first).
- Speed is measured **from the pose** over `PHYSICS_FRAME_DT`, not PhysX's velocity (angular reads 0.02-0.03 rad/s high); the `platform/odom` twist too (`VelCtl.outputs:odom_lin/odom_ang`).
- `Diff` max speeds = `VELCTL_HEADROOM` (4) × limit; the command is clamped to the real limit in `VelCtl`.
- PGS + CCD on wheels (`enable_wheel_ccd`): TGS barely turns skid-steer robots. Keep `wheel_radius` etc. at the real calibrated values.
- Didn't help the skid-steer rotation dead zone (don't retry): wheel friction, drive damping, 360 Hz physics.
- Why the yaw loop has to work so hard: PhysX friction is rigid Coulomb, no tyre compliance, so a skid-steer chassis barely yaws until its wheels slip outright (j100_0921 open loop: ~2 % of the commanded yaw rate in place at 0.3 rad/s *and* in arcs, whatever the friction). The integral supplies the slip; with too much of it (default ki_w 10, limit 3) it swings in a stick-slip limit cycle. `vel_ctl`'s optional 7th/8th values `ff_v`/`ff_w` scale the feed-forward (out = ff * cmd + kp * e + integral); `wheel_friction` puts a physics material on the wheels (`apply_wheel_friction`; none = PhysX's 0.5/0.5 averaged with the ground's 1.0/0.9). j100_0921's tuned values and numbers are in `model_params.yaml`; measure with `scripts/vel_tune/step_test.sh`.
- **Calibrating a model (either engine) means tuning `wheel_friction` together with `vel_ctl`**, per engine (`robots.<m>` for PhysX, `robots.<m>.newton` for Newton):
  1. Check the friction reaches the contact first: under Newton the `FLEET_DEBUG=1` dump's wheel geoms must show the `wheel_friction` value and `priority=1` (they once sat at the default 1.0, and MuJoCo takes the larger of two geoms' friction), and the ground must be the plane (`newton: ground collider = a plane` in the log). Gains tuned on a wrong contact chase a physics artefact.
  2. Open loop (`VELCTL=0`): `step_test.sh <robot> <label>` and `calibrate_velocity.py`. Adjust `wheel_friction` until the raw response is smooth (low wobble, no stick-slip at 0.1 rad/s): more friction = more skid-steer stick-slip and a weaker in-place turn, less = smoother arcs but a slippery slow turn (j100_0921 on Newton: 0.2 helped arcs, hurt 0.1 rad/s turns; 0.3 kept).
  3. Then `vel_ctl` (`VELCTL=1`): feed-forward `ff_v`/`ff_w` ~ 1 / the open-loop ratio, the integral for the rest; P only if it doesn't add overshoot. Verify with both tools (`calibrate_velocity.py --physics-hz <engine's Hz> --sim-rate-hz <SIM_RATE_HZ>`: within 10 %; step test: wobble, overshoot).
  4. A friction change (or Newton `wheel_max_force`) changes the open-loop ratios, so redo 2-3 after it. Both take effect at the next spawn (`docker restart a300-isaac-sim`; wait on `docker logs --since <restart time>`, a restarted container keeps its old log).
  5. `scripts/vel_tune/calibrate_all.py --jobs <model>:<physx|newton> ...` automates 1-4 per model on the empty scene (friction 0.3/0.3 min; Newton: `wheel_max_force` from the mass, x1.5 if the sweep saturates; PhysX gains from the hand-tuned sibling's yaw loop; up to 3 closed-loop tries, best kept) and writes `model_params.yaml`; progress/resume in `sim/generated/vel_check/calibrate_all.json`. It drops the base station's relays of a real robot it calibrates and restores the fleet settings at the end. Newton turns still start with a ~0.2 s breakaway spike (50-130 % over a step command), which the gains can't remove: it is the wheel-damping artefact above, gone on j100_0921 with `wheel_damping` 20 (step overshoot 1-9 %).

### Resting stillness

- `WHEEL_BRAKE_SCRIPT`: with zero command and wheels < 0.05 rad/s (or after 1 s), latches wheel angles as position targets at `WHEEL_BRAKE_STIFFNESS` 1e4; any command resets stiffness to 0. Needed because wheel drives are pure velocity dampers, so idle robots rocked.
- `ARTIC_VEL_ITERS` (8) on every articulation root stops contact jitter; extra position iterations only cost fps.

### Ridgeback (r100, `drive: omni`)

- Same `Diff` graph for forward/rotation; a `BodyDrive` ScriptNode (`Articulation.get/set_velocities` on the root) replaces the body-frame lateral velocity with the commanded `vy` (fed back, `VELCTL_LATERAL`) and sets the yaw rate. Wheels don't spin while strafing.
- Not `HolonomicController`/mecanum wheel speeds: wheel collisions are plain cylinders (rollers are visual-only) and this PhysX has no anisotropic friction, so no sideways thrust; driving the wheels made rotation wrong.
- Limitation: a small pure in-place rotation from standstill (~0.5 rad/s) is mostly absorbed by static friction.

### Lidars (`LIDAR2D_READ_SCRIPT`, `LIDAR3D_READ_SCRIPT`)

- Rays cast per frame with `get_physx_scene_query_interface().raycast_closest` (directions via numpy); no sensor prims. Rays start at `range_min`; misses +Inf (2D) / dropped (3D).
- 2D: 541 rays over ±2.356 rad, 0.1-10 m, `LaserScan`. 3D (VLP16): 16 × 360 rays, ±15°, 0.4-30 m, `PointCloud2` on `sensors/lidar3d_0/points`, pose = chassis × the lidar's offset from it, spread over `LIDAR3D_TICKS_PER_SCAN` (4) frames.
- Not `isaacsim.sensors.experimental.physics` `Raycast`/`RaycastSensor`: its per-step update segfaulted the sim (exit 139) and its `depths` are wrong. The IMU still uses that plugin (`IMUSensor`), never seen crashing; suspect it first on a step-time segfault.
- Never author prims under an instanceable subtree (e.g. a200's `sensor_arch`): instance-proxy error, and retrying per tick crashed the sim. Parent under a non-instanced prim with an explicit offset.

### Cameras

- `CAM_FAR_CLIP` 120 m. Depth limited to the real sensor range (`DEPTH_RANGE_M`: D435i 0.28-10, D405 0.07-1, ZED 2i 0.3-20 m), out-of-range = 0 like the real drivers: `install_depth_range_limit` wraps `rep.writers.get` and swaps in a `distance_to_image_plane` annotator with a Warp augmentation, **registered by name** (the helper deep-copies the writer; an `Annotator` object doesn't copy). Failures only log.
- **On demand** (`CAMERA_ON_DEMAND`, `camera_on_demand_loop`): `HydraTexture.set_updates_enabled` on only while a topic has a subscriber (polled 0.5 s, off `CAM_IDLE_OFF_S` 2 s later); textures from `ViewportManager()._hydra_textures`. Not `IsaacCreateRenderProduct.inputs:enabled` (keeps rendering). No round-robin/per-frame toggling: it's slower than always on.
- Every camera renders `CAM_WARMUP_S` (5 s) after play/spawn/reset, so its publisher exists; otherwise `ros2 topic hz/echo`/Foxglove never subscribe.
- j100_0921 / a200_0333 images are upside-down (real mount).

## Time

- `/Graphs/fleet_clock` (`build_clock_graph`) publishes `/clock` from `IsaacReadSimulationTime`; robot graphs' `Stamp` node stamps everything (`IsaacReadSystemTime` if `USE_SIM_TIME=false`), script nodes via a `stamp` input.
- `resetOnStop=False`, and camera helpers `useSystemTime=False`, `resetSimulationTimeOnStop=False`: otherwise time jumps to 0 on spawn/reset.
- `SIM_RATE_HZ` (compose default 20, the profile 30 since 2026-10-20: a divisor of 60 and 240, see "Physics engine") ≈ the `render_fps` of `FLEET_DEBUG=1`; `PHYSICS_HZ` 60. Kit runs `floor(PHYSICS_HZ / SIM_RATE_HZ)` steps per frame, so a non-divisor makes `FLEET_DEBUG`'s rtf overstate; `/clock` counts physics time and stays right. `PHYSICS_FRAME_DT` = true step per frame.
- FPS levers (README *Faster streaming*): async rendering via `FLEET_SETTINGS`, fewer robots, `CAMERA_STREAMS=none`, cameras on demand; resolution/viewport size don't matter. `FLEET_MERGE_FIXED=1` breaks the build (merges away `camera_0_link`).

## Model parameters

Derived at start (`load_model_params`/`derive_model_params`, logged `[fleet] params <m>:`): drive from `platforms[<platform>]` in `model_params.yaml`, replaced by robot.yaml's `platform_velocity_controller` calibration; sensors/arm/IMU body from robot.yaml + flattened URDF + `merged_links.json`; then `robots[<m>]` hand overrides. Arm drives: `configure_arm_drives` (`ARM_DRIVE_*`, `ARM_EFFORT_SCALE`).

## Cutter + gripper end effector (`end_effector: ee_cutter` in `model_params.yaml`, `ee_cutter.py`; j100_0921)

- The real EE replacing the 2F Lite's fingers: assets `sim/assets/ee_cutter/` (STEP → `step_to_glb.py` → Blender `make_ee_cutter_looks.py` → `cutter_gripper.usd`, textured). `ee_cutter.attach` at spawn (after `configure_arm_drives`), before play: the 2F Lite fingers' instanced visuals/colliders are deactivated (links and joints stay: `arm_0_gripper_right_finger_bottom_joint` is the gripper MoveIt/`moveit_sim_bridge`/joint_states know); the static parts go under `arm_0_gripper_gripper_base_link` (colliders on the jaw, the counter-blade and the housing: `STATIC_COLLIDERS`, `HOUSING_COLLIDERS`); 7 bodies + driven joints `ee_cutter_{slide,pusher,link_1,link_2,finger,blade,spur}_joint` (each body references the whole USD with the other parts deactivated: the materials sit outside the parts). The linkage pins are parts of their own (`pin_*`): a new moving part has to be added to its body's list in `BODIES`, or it stays with the static parts.
- EE vs the robot's own basket (`ee_cutter.contact_with_robot`, 2026-10-30): self-collisions are off for every robot, so the EE passed through `unloader_wall_*`. For j100_0921 they are on, and `physics:filteredPairs` on every collider pair of different bodies except EE vs `CONTACT_LINKS` keeps all else apart (the robot is de-instanced first: no filter on an instance proxy). Newton's MuJoCo solver needs three more things, each found the hard way: (1) it filters by *weld* body, so everything on fixed joints shares the chassis' or `arm_0_end_effector_link`'s exclusion: the wall joints and `arm_0_gripper_gripper_base_joint` become hinges locked to ±0.01°; (2) `convexDecomposition` pieces are made at parse time as shapes no prim stands for, so filters miss them (they collided with the arm links): the jaw and counter-blade (and since 2026-11-02 the blade, its gear and finger_tip, `DECOMPOSED`: their single hulls held cut pieces after the release) are split with CoACD at spawn (`decompose`, Newton's settings) into invisible convex-hull prims; (3) shape filters only reach MuJoCo where a body pair isn't fully filtered, through geom colours. Check offline: build the stage with `attach`, `newton.ModelBuilder.add_usd`, `SolverMuJoCo(use_mujoco_contacts=True)`, then compare geom contype/conaffinity, `body_weldid`, `exclude_signature` (EE vs walls: 45 pairs collide; other robot pairs: 0). Verified live by swinging the lowered EE into the walls: the arm is pushed up to 0.69 rad off its other joints (0.003 rad above the walls). The arm's drives are strong enough that it rides over a wall rather than stopping dead.
- `mtu32_description`'s `ee_cutter_link` (colcon_ws) is the EE for RViz (a mesh) and MoveIt (boxes); in the sim its geometry is deactivated (`URDF_ENVELOPE`): the parts show and collide instead.
- Mechanism (user, 2026-10-29): the 2F Lite carriage slides the crossbar (CAD `finger`) away from the arm to close; wing pin → link_pusher → link_1 → link_2 → finger_tip against gripper_base's jaw. The `EeCutter` ScriptNode reads the 2F Lite joint every tick and sets the exact closed-loop targets (`ee_cutter.targets`; the loops are closed by targets, not constraints, so both engines run it): Kinova 0 = CAD pose (open), 0.96 = 14 mm slide, finger_tip -88.7 deg at the jaw's horn. Blade: `pruner/blade` (Float64 0..1) → 0..80 deg at `BLADE_SPEED`, spur gear at -5.05x; `robot/bin/pruner_stub` cycles it per pruner command.
- Foam pads (`add_pads`, `PAD_*`, user 2026-10-30, sim only: not on the real EE nor in `ee_cutter_link`): black convex pieces on the jaw's curve (static) and finger_tip's inner arc (finger body), each filling half the pocket less `PAD_GAP` 1 mm when closed (7-19 mm thick; 3 mm until 2026-10-31, for 5 mm stems); `FOAM` material: friction 1.0/0.9 combine max, PhysX compliant contact 25000 N/m (5000 until 2026-11-01: a 2 mm stem sank its whole radius into a pad, popped through or stayed embedded and rode back out of the basket). Both pads touch the gripped stems (contact log, 2026-10-30); cut_stem runs: 8/15 and 6/7 cut pieces in the basket with the old 57x-too-stiff plant, 6/13 with the corrected one.
- CAD frame → gripper_base_link: x→y, y→z, z→x (+2.2 mm): the gripper_base holes land on the 2F Lite finger axes, the D405 bracket on camera_1's side. Self-check: `python3 sim/scripts/ee_cutter.py`.

- Kinova Gen3 lite base mount kit (`arm_base_mount: <m>` in model_params, j100_0921: 0.048): `sim/assets/kinova_base_mount/kinova_base_mount.usd` (Blender `make_kinova_mount.py`, from photos, 48 mm tall, visual only) referenced under `arm_0_base_link` at spawn, its foot that far below the arm base (on the plate).

## Robot looks (`ROBOT_LOOKS` full|basic|0, `robot_looks.py`)

- `apply_robot_looks(models)` at spawn, once per model: OmniPBR looks from `/sim/generated/looks/looks_<mode>.usda` via `RULES`/`MODEL_RULES` (hue judged in sRGB); procedural textures cached by stamp, cubic projection (no UVs) scaled per mesh unit to `TILE_M`. Errors only log. One-mesh sensors with a glass front (`FRONT_GLASS`: the D405, matte aluminium casing) get a `GeomSubset` of their front faces (by normal, in instances.usda) bound to `glass_black`. Raised lettering (`LETTERING`: KINOVA on the Gen3 lite's `arm_link`/`forearm_link`, a box per mesh) gets a subset in its own look: the steep walls plus what they enclose above them. Kinova meshes (`CREASE_LOOKS`) get authored faceVarying normals, smooth within `CREASE_DEG` (35): the STLs have none, and the renderer smoothed across every edge (streaks on the long CAD triangles). Parts painted by region (`REGIONS`, after `CUTS` splits faces at a plane so a region can end there): the Duro antenna (`gnss_spherical`) is a polished white dome, a dark rubber band on the rim's upper 5 mm and a cream base; the cut mesh's points/topology are authored over the referenced ones in instances.usda (in memory).
- Visual meshes are instance prototypes, so bindings are retargeted **in memory** in each model's `payloads/instances.usda` / `base.usda` (`Sdf.Layer.FindOrOpen`, never saved, kept in `_held_layers`). Only all-purpose `material:binding`. One prim per tint colour.
- Snapshots: `FLEET_SNAPSHOT=<dir>`, or `fleet_ctl.py snapshot [--poses '{"<ns>": [x, y, yaw]}'] [--views front,rear,close,wide] [--tag T]` → `sim/generated/snapshots/`. Pass `ref_pose` as `--poses` after driving (the USD transform can lag).
- Viewport view: `fleet_ctl.py camera X,Y,Z X,Y,Z` (eye, target; world m) aims it and keeps it across spawns/snapshots until the sim restarts (`camera default` drops it).
- Recording: `fleet_ctl.py record NAME [--fps 10] [--res 1920x1080]` saves the viewport (its render, so a locked screen or headless works) as `sim/generated/recordings/NAME/frame_%06d.jpg` + `frames.csv` (wall/sim time), and the VBD plant's close-up view as `close_%06d.jpg` once `camera --view close` opened it; `record --stop`. Encode with ffmpeg afterwards.
- Sun: `fleet_ctl.py sun HOUR | --from H --to H --duration S` (`sun_request`): the scene's sun at the solar position of a local time at `SUN_SITE` (Houghton, MI, June 21, EDT; NOAA approximation), fixed or moving over wall-clock seconds; one orient op on `/World/Lights/sun`. A low sun behind the a300 puts its mast's shadow on the Wiferion tag and docking fails (2026-10-28: 8:00-11:00 and 19:00 failed, 12:00 and 18:30 docked).
- Clouds: `fleet_ctl.py clouds [--cover 0.4] [--speed 2] [--heading 70] [--altitude 300] [--seed 1] | off` (`clouds_request`): one 6 km quad at `altitude` with a tileable fractal-noise opacity texture (`cloud_texture`, cached in `sim/generated/clouds/`; fractional cutout opacity on), drifting toward `heading` and wrapping at one tile. What shows is its shadows crossing the field; the robot cameras' 120 m far clip leaves the layer itself out of their image. In `NEWTON_IGNORE_PATHS` always. Both lost on a sim restart.

## Scenes (`SIM_SCENE`, `build_world`)

- Empty: `build_default_world` (80 m ground box, top z=0, dome + sun; RTX ignores `displayColor`, so bind a material). `lavender`: built-in farm. Otherwise a file in `sim/scene/` (`build_file_world`; the imported profile has `lavender_farm_chargers.usda`).
- A file is a **sublayer** of a new stage (relative `../assets/...` resolve, the file is never written); `setup_physics` is authored over its physics scene; default ground/lights only if it has none; what the sim adds itself (saved robots, `/Graphs`, `soften_lavender`'s `lavender_cores`/`collisionGroups`, `/World/FarmWorkers`: a Save As of the running sim has them) is removed in memory from **every layer** of the file (`scene_layer_stack`): a Save As of a sim that ran a saved file has that file, with all of it, as its sublayer (the old top-layer-only cleanup died on its `/Graphs/fleet_clock`). Ground at z=0 within ±`SPAWN_LIMIT`. Spawn-map rows: `customLayerData["lavender_rows"]` (`[x_min, x_max, y, width]`) of the topmost layer that has them (a Save As writes none); `charging_stations` (`scripts/make_charger_scene.py`) the same way → `state.json` `chargers` (world x/y, `yaw_deg` = the side the tag faces), plus `tag` (the AprilTag mesh's centre, from its points: Kit's `BBoxCache` gives it an empty box) once the first frames ran. The robots' `battery_sim` charges there, and `sim_robot_upstart` turns them into Nav2 docks (`charger_docks`).
- The sim user (uid 1234) saves only into writable folders: `chmod 777` a new `sim/scene/` subfolder.
- Vegetation (NVIDIA `Assets/Vegetation/...` in `sim/assets/trees|shrubs|rocks/`) needs its `materials/`/`textures/` and the `sim/assets/Trees -> trees` symlink, or renders red; Z-up/cm, referenced under a child prim. `Cedar_Shrub` is unusable (empty bbox). Ground cover: one unscaled patch only (tiling exceeds the instance limit; geometry is metres despite `metersPerUnit=0.01`).

### Soft lavender (`soften_lavender`, `LAVENDER_SOFT`, default 1)

- On `/World/lavender` in any scene: collision group `soft_plants` filtered against `robots` (`spawn_robot` adds each robot), so robots pass through foliage while lidar raycasts still hit it. Guide-purpose cylinder cores (r 0.1 m, h 0.3 m) at each plant's bbox centre (`/World/lavender_cores/`) stop robots at the crown; rows can't be crossed.
- Inverted groups (`invertFilteredGroups=True`) are ignored in Isaac 6.0; use the explicit pair.

### Real field: `sim/scene/lavender_farm.usd`

- Rebuild: `scripts/make_farm_scene.py` (farm DB `public.object_data` via status_server's `config.yaml`) runs `build_farm_scene.py` with plain `pxr` in the Isaac image (no Kit; running sim untouched). Without the DB: `build_farm_scene.py` on `sim/generated/farm/plants.json`. Map frame = sim world frame.
- Self-contained apart from `../assets/...`: colliders live on abstract class prototypes `/World/Prototypes/*` (traverse with `Usd.PrimAllPrimsPredicate`).
- Plants at DB x/y, scaled uniformly (per-axis looks squeezed) to `PLANT_DIAMETER` 0.99 m × a per-plant random `PLANT_SIZE_RANGE` 0.9-1.1 (seeded by `object_id`, like the yaw; `customData` `diameter_m`), lanes ~0.86 m clear. Models (`sim/assets/lavender_v2/`, from the Sim_LavenderFarm pack): `LAVENDER_READY` 01/02 (flowering) in exactly 70/30 (which plant seeded by `object_id`), `LAVENDER_HARVESTED` 05 (flowerless, `LAVENDER_HARVESTED_SCALE` 0.5 of the plant width; no colliders, invisible until harvested); each plant is an Xform with `ready`/`harvested` instance children, prototypes normalised to 1 m wide (`add_plant_prototype`) so both share the plant's transform. `LAVENDER_SUBSURFACE` on the stem/leaf shaders (the pack's MDLs patched to expose it; opacity isn't see-through, the colour is what shows). `FIELD_BOX_MARGIN` (not plant size) sets the border's field box, so resizing plants keeps the border.
- Border (`BORDER`, `scatter_points`): seeded random trees/shrubs/rocks over the 100 m ground beyond per-group distances (±`EDGE_JITTER_M`), no overlaps; clearing (spawn poses, charger) stays open. Lights: `SKY_INTENSITY`, `SUN_INTENSITY`, `SUN_ROTATE_XYZ`.
- Weed barrier (`add_weed_barrier`, visual only): strip per row, `BARRIER_WIDTH` 0.9 m, over per-plant soil mounds (`MOUND_*`) burying stem bases; `hide_grass_under` hides grass on strips. Ground: `/World/ground` is guide purpose (collider), `/World/ground_surface` a textured quad. Textures from `make_farm_textures.py` (host python, numpy + Pillow).
- Materials (`textured_material`): OmniPBR with low `specular_level` + `UsdPreviewSurface` fallback; `UsdPreviewSurface` alone mirrors the sky white at grazing camera angles.
- Arch (`add_arch`): `wood_arch.usd` at `/World/arch` across lane `ARCH_LANE` (0 = northernmost), `ARCH_SETBACK_M` before the shorter row's west end.
